Design patterns

Builder

agent.New(id, name).WithModel(...).AddTool(...).Build() assembles an agent immutably before use.

Adapter

Every storage/vector backend implements a common interface and is selected by config — swap SQLite→Postgres with no code change.

Chain / middleware

hooks.Chain composes multiple Hooks; Before/After wrap every model and tool call.

Registry

tool.Registry and skill.Registry hold dynamically registered definitions looked up by name at call time.

Interface segregation

Relational Storage is deliberately separate from VectorStore — a backend implements only what it supports.

Context propagation

Tenant identity and stream emitters travel on context.Context, so cross-cutting concerns need no signature changes.

Durability & concurrency notes

  • Checkpoint ordering. The runner computes the next node before persisting, and writes the checkpoint + ledger event together — a crash resumes at the not-yet-run node, never re-running a completed one.
  • Resume semantics. Resume skips the interrupt it paused at exactly once; any downstream interrupt still pauses for approval.
  • Panic isolation. Node functions run under panic recovery, so one bad node fails only its run.
  • MCP concurrency. stdio calls are serialized under a mutex with read deadlines honoring per-call context; Close force-kills a hung subprocess. SSE responses are correlated by JSON-RPC id and delivered by a background reader.
  • Queue safety. Leases with heartbeats, orphan recovery on lease expiry, idempotency keys, and a reliable outbox guarantee at-least-once effects without duplication.
  • Tenant enforcement. Writes stamp the tenant from context (unspoofable); reads filter by it; cross-tenant id lookups return not-found, closing IDOR.
  • Back-pressure. The team protocol bus bounds handler goroutines and per-peer inboxes, dropping to explicit "saturated"/"inbox full" errors rather than blocking.
